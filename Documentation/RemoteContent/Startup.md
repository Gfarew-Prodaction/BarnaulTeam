# Проверка сервера → меню → игровое лобби

Открывай `Assets/Scenes/Startup.unity` для запуска в редакторе. В глобальном списке сборки Startup стоит первой, SampleScene второй. Если профиль сборки переопределяет список сцен, добавь обе сцены в таком же порядке.

StartupFlow создаёт world-space экран, камеру, EventSystem и отдельный persistent-загрузчик. В редакторе кнопки доступны мышью; в шлеме наведи луч любого контроллера и нажми курок. Положение экрана при старте: (0, 1.55, 2). При необходимости отцентрируй вид в шлеме.

После проверки сервера и скачивания всех картинок открывается меню. «Войти в игровое лобби» асинхронно загружает SampleScene. Это текущая игровая сцена проекта; отдельная сцена лобби пока не создавалась. Имя можно поменять в StartupFlow → Lobby Scene. Стартовая камера, меню и лучи уничтожаются при смене сцены, загрузчик продолжает жить. В игровом лобби используется существующий HurricaneVR-игрок.

При сбое сети показывается «Повторить загрузку». При наличии сохранённого набора также доступно «Продолжить с сохранёнными данными». Без данных войти в лобби нельзя. Новый запуск заново проверяет сервер. Стартовый загрузчик использует Catalog Url по умолчанию из RemoteElementContent. Не добавляй второй RemoteElementContent в игровую сцену.

После загрузки сцены загрузчик автоматически связывается с ElementDog всех её корней, включая неактивные. Data по-прежнему запрашивается у ElementDog; ID должен совпадать с JSON. Наполнение карточек и обработчики Interact/Pointed остаются задачей игрового UI.

Проверка на устройстве: первый запуск онлайн → меню → лобби; запуск без интернета с кешем → продолжить → лобби; без кеша и интернета → только повтор загрузки; обновлённый JSON → новая версия в меню. Компиляция проверена отдельно; VR-ввод и переключение сцен требуют проверки в Unity/Quest.
